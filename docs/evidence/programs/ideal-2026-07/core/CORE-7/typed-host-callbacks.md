`calcvba-host-api` contains the host contract, exact runtime value carriers and
sealed scalar/object argument families. It depends on oxvba-runtime/thiserror;
there is no compiler, HAL, VM3, JIT, spreadsheet or libffi dependency. Library code
uses RuntimeProvider/Session; the app supplies oxvba-embed's Provider. API ABI 1
and typed-entry ABI 2 are checked/advertised. This is a linked Rust interface
with owner-local Box/Rc/drop allocation, not a stable dynamic C/plugin ABI.
Source-free verified packages remain open. The API facade reuses the existing
source-module compiler, session owner, checked generation and replacement reload.

The API publishes compiler-owned signatures (Function/Sub/accessors, visibility,
Option Private, exact parameter/array metadata, passing modes/defaults), opaque
handles, explicit dynamic calls and typed-slot calls. Clients can bind/type a
Property Get. Wrong owners, stale generations and forged provider payloads refuse.
Native early-bound host objects still use the real supplied resolver and HAL:
the native-host test exercises both the original facade and API facade with one
preserved-IID/slot vtable call and zero Invoke/name/type-info recovery per call.

The portable typed subset adds borrowed host objects, Double-returning slots with
zero arguments or one required ByVal Long, and mixed numeric/object procedure
argument positions. It uses the original OxFunc plus shared checked physical
layout and retained interface descriptors. Unsupported shapes are refused before
binding; IID, table bounds and exact native signature are checked before entry.
JIT emits a typed call_indirect; VM3 invokes the same native signature. Both use
unboxed slots/output, with no Variant argument vector/frame or libffi. API slot
thunks enter the same native primary functions. Ordinary dynamic/native COM calls
keep their existing carrier ABI; they do not reinterpret a COM pointer as a host
table or silently retry a typed refusal.

HostObject owns immutable tables and callback captures through same-thread Rc.
ObjectArg carries a lifetime-bound pointer with complete-allocation provenance;
its prefix is the runtime IUnknown, separate from the typed callback table.
The native-prefix test retains/QIs/releases the exact identity after the Rust
owner drops, and verifies final capture release. Installed nightly Miri passes
that focused test. This is bounded ownership evidence, not general COM serving.
Extended Miri found a cached pointer invalidated by moving its boxed table; the
table now uses immutable Rc storage. Physical object slots now retain pointers
in an eight-byte union rather than converting them through integer addresses.
The final strict-provenance Miri run passes all eight callback tests on VM3,
including the active-invocation descriptor test. This caught and corrected the
table lifetime defect without disabling alias/provenance checks. Miri executes
the interpreter, not machine code generated by Cranelift.
No invocation pointer or object-count cap of 4,096 is stored by this mechanism.
Host callbacks must resolve active backend/caller context themselves. A retained
descriptor test refuses absent/wrong-sheet views and resolves successive active
values 41 and 82 without retaining either invocation's view. Owning typed objects
in VBA globals/Static/results remain delivery bead `bd-59co.2.10.10`.

Typed callbacks can synchronously reenter the same session with the borrowed
active context. Nested blocks consume its budget. Fresh-context, dynamic-call
and reset attempts on that session refuse. A thread-wide limit of 64 typed
activations also covers calls across independent sessions (VBA error 28).
Success, callback faults, panic/error 5 and budget interruption unwind guards and
leave the session usable. Failed callbacks never expose an unwritten output.
Reload requires an exclusive mutable session borrow, which cannot coexist with
the shared borrow spanning a safe call/callback. Review also tightened admission
to refuse object value comparisons/conditions, rather than treating pointer bits
as scalar values; the negative physical-layout regression covers both forms.
Typed entries still reject owning object results, persistent VBA object storage,
ByRef, strings/arrays, globals/Static, handlers and general internal recursion.

The Range-like fixture executes actual VBA `root.Read(offset)` and
`root.NumericValue` through both backends. Other tests cover mixed argument ABI
positions, retained ownership, bad IID/slot/signature, host faults/panics, shared
budget, recursive depth and recovery, descriptor ambiguity, generations and reload.
Instrumentation over 1,000 warm API -> VBA -> host -> same-session VBA calls per
backend records zero heap allocations, zero owning Variant constructions and zero
live-carrier drift. These observations exclude preparation/binding and failure
paths; they do not establish a speed claim.

Generic numeric arithmetic separately resolves project/foreign default members
without replacing the object parameter. The Range-like dynamic host test proves
TypeName/IsObject/identity and numeric 41 -> 42/82, text "3" -> 4, blank -> 1,
bad text/multi-value -> error 13; Nothing/default faults remain errors. The project
class test also checks caller-frame/handle balance. Live-Excel status and final
repository checks are recorded below. No members were added to
adapters/spreadsheet-compat and no DNA Calc migration is claimed.
